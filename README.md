# RoyalStay – Hotel Room Booking System

ASP.NET Core MVC (.NET 8) + SQL Server hotel booking website.
Guests can browse rooms, check availability and book. An admin can log in to manage rooms and bookings.

## 1. Technology stack
- ASP.NET Core MVC, C#, .NET 8
- SQL Server / SQL Server Express (ADO.NET with `Microsoft.Data.SqlClient`, parameterized queries, transactions)
- Razor views, HTML, CSS, JavaScript, Bootstrap 5 (CDN)
- Cookie authentication, PBKDF2-SHA256 password hashing
- Visual Studio 2022

## 3. Features

### Implemented
- **Admin login / logout** (cookie auth). All `/Admin/...` pages need the `Admin` role. Passwords are stored as PBKDF2 hashes (never plain text). Server-side validation, anti-forgery tokens on every POST form, local-only return URLs, and a simple lock-out (5 wrong tries → 5 minutes).
- **Room management (admin):** add, view, edit, delete. Validation for room number (unique, letters/digits/`-`), room type, price (1–1,000,000), capacity (1–10), description, image URL (must be http/https). A room that has bookings **cannot be deleted** – the admin is told to untick "Available" instead.
- **Guest booking:** list of rooms from SQL Server, availability search by dates + guests, booking form. Booking ID is generated by SQL Server (`IDENTITY`), total = nights × room price (calculated on the server from the database price), dates validated (not in the past, check-out after check-in, max 30 nights), guests ≤ room capacity, **overlapping bookings for the same room are blocked** (inside a SERIALIZABLE transaction with a lock on the room row).
- **Booking management (admin):** list all bookings, filter by status, change status (Pending / Confirmed / Cancelled / Completed). Re-activating a cancelled booking re-checks for overlaps.
- **Booking confirmation page** (data read back from SQL Server) and **admin dashboard** (room/booking counts, revenue).
- **Guest "My bookings":** guest enters the email **and** phone number used for booking and sees only those bookings.
- Original UI/design kept (same CSS, layout and pages).

### Not implemented
- Guest registration / guest login (guests book without an account).
- Online payment, e-mail/SMS confirmation, booking cancellation by the guest.
- Image upload (rooms use an image URL).
- Automated unit/integration tests.

## 4. SQL Server setup

### Option A – run the SQL script (easiest)
1. Open **SQL Server Management Studio (SSMS)** and connect to `DESKTOP-VVQM1KOU\SQLEXPRESS` (Windows Authentication).
2. Open `database/HotelBookingDB.sql` → press **F5**. It creates `HotelRoomBookingDB` (if missing), the tables, constraints, 3 sample rooms, 1 sample guest and 2 sample bookings. It is safe to run again; it never drops or renames anything.
3. *(Only if you already have tables with data)* compare your columns with the table in section 4a below before running.

### 4a. Expected tables (what the application code uses)
| Table | Columns |
|---|---|
| `Users` | UserId (PK), FullName, Email (unique), PasswordHash, Role (`Admin`/`Guest`), CreatedAt |
| `Rooms` | RoomId (PK), RoomNumber (unique, text), RoomType, Price, Capacity, Description, ImageUrl, IsAvailable |
| `Bookings` | BookingId (PK), UserId (FK), RoomId (FK), GuestName, GuestEmail, GuestPhone, CheckIn, CheckOut, Guests, TotalAmount, Status, CreatedAt |

> **Note:** the original project had no SQL file, so the script was written from the SQL queries in the application code. Columns `RoomType`, `Capacity`, `Description`, `ImageUrl` (Rooms) and `GuestPhone` (Bookings) are **added only if missing**.

### Option B – restore the backup (`HotelBookingDB.bak`)
1. Copy `HotelBookingDB.bak` to a folder SQL Server can read, e.g. `C:\Temp\`.
2. SSMS → right-click **Databases** → **Restore Database…** → choose **Device** → click **…** → **Add** → pick the `.bak` → **OK**.
3. Make sure the destination database name is `HotelRoomBookingDB` → **OK**.

### How to CREATE the `.bak` (for the submission)
The `.bak` must be made on your computer (it cannot be created without your SQL Server):
1. Run the app once (section 6) so the admin account exists, and make 1–2 test bookings.
2. SSMS → right-click `HotelRoomBookingDB` → **Tasks → Back Up…**
3. Backup type: **Full**. Under *Destination* click **Remove** (if a path is listed), then **Add…** and type a path such as `C:\Temp\HotelBookingDB.bak` (create the folder first).
4. **OK**. Copy the file into `HotelBookingSystem/database/`.

(Or in a query window: `BACKUP DATABASE HotelRoomBookingDB TO DISK = N'C:\Temp\HotelBookingDB.bak' WITH INIT;`)

## 9. Design decisions
- **Kept the original UI** (CSS, layout, page flow). Only what was needed was changed: static sample rooms → database rooms, fake "Login/Register" buttons → real Admin Login/Logout, "My Bookings" now asks for the email and phone used at booking.
- **ADO.NET with parameterized queries** (as in the original code) – no string concatenation of user input into SQL.
- **Overlap rule:** `existing.CheckIn < new.CheckOut AND existing.CheckOut > new.CheckIn`, ignoring `Cancelled`. Same-day check-out / check-in is allowed.
- **Transactions + locks:** booking creation locks the room row (`UPDLOCK, HOLDLOCK`) so two guests cannot book the same room at the same time.
- **New bookings start as `Pending`** so the admin's status update has a purpose (the old code saved `Confirmed`).
- **Room deletion** is blocked when bookings exist (FK has no cascade), to protect booking history.
- **Guests:** stored in `Users` with role `Guest` and a placeholder hash that can never log in.
- **Admin seeding from configuration** so no password is hard-coded in SQL or C# code.
- Added columns (`Capacity`, `GuestPhone`, etc.) are added non-destructively; nothing was renamed.

## 10. Testing performed

### Verified in the final review session (Linux sandbox, .NET 8.0.132 SDK)
- The project **compiles with 0 errors and 0 warnings**, including Razor view compilation. **Limitation:** the sandbox could not download NuGet packages, so this build used a small stand-in for `Microsoft.Data.SqlClient`. The real package (`Microsoft.Data.SqlClient` 7.1.1, listed in `RoyalStay.csproj`) is restored when **you** build in Visual Studio – please confirm the build there.
- The app **starts** and `/Account/Login`, `/Rooms`, `/Bookings/MyBookings` return HTTP 200.
- `/Admin`, `/Admin/Rooms`, `/Admin/Bookings` and `POST`-style URLs such as `/Admin/Rooms/Delete/1` **redirect to the login page** when not logged in (HTTP 302); a login POST **without** an anti-forgery token is rejected (HTTP 400).
- `HotelBookingDB.sql` passes a T-SQL **syntax** parser check (16 batches, `sqlglot`). This is a syntax check only – the script was **not executed** on SQL Server.

### NOT verified (no SQL Server or working CDN in the sandbox – please run on your PC)

- Whether an already existing `HotelRoomBookingDB` matches the script.
- Visual/responsive layout in a browser and all screenshots.
- The `.bak` file (must be created by you).

## 11. Known issues / limitations
- "My bookings" is protected only by knowing the email **and** phone number (no guest login / OTP). This is simple, not strong, protection.
- Login lock-out counters are kept in memory and reset when the app restarts.
- The authentication cookie requires HTTPS (use the default `https://localhost:50632` URL).
- Room images are external URLs and need internet.
- If `Rooms.RoomNumber` in your existing database is a number type instead of text, change it to `NVARCHAR(20)` (the original code already read it as text).
